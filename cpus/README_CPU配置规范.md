# CPU 性能配置文件制作规范

> 本目录（`cpus/`）用于存放**每个 CPU 型号一份的独立性能配置**。
> 程序启动时自动识别当前机器 CPU → 加载对应配置；识别不到的型号自动按内置公式运行（不会报错）。
> **新增配置无需改动任何源码，放进本目录即自动生效。**

---

## 一、文件命名规则

| 规则 | 说明 | 示例 |
|---|---|---|
| 后缀 | 必须是 `.yaml` | `AMD_Ryzen_7_8845HS.yaml` |
| 命名 | 用 **CPU 型号**（含厂商），其中**空格与特殊字符换成下划线 `_`** | `Intel_Core_i3-4160.yaml` |
| 建议 | 去掉 `(R)`/`(TM)`/**CPU** 等修饰词，保留官方型号主体 | `AMD_Ryzen_5_5600.yaml` |

程序同时支持以下写法（匹配时自动归一化，**不区分大小写**）：
- 下划线命名：`AMD_Ryzen_7_8845HS.yaml`
- 空格命名：`AMD Ryzen 7 8845HS.yaml`（Windows 下也可）
- 括号包含：`Intel(R)_Core(TM)_i5-12400F.yaml`（会自动解析为 `Intel Core i5-12400F`）

> 启动程序时日志会打印 `[CPU] 检测到: xxx`——把该名称按规则转成文件名，就是**最稳的命名**。

## 二、字段说明（全部可留空，留空=按内置公式自动算）

```yaml
# ======== 识别部分 ========
model: "AMD Ryzen 7 8845HS"     # 【建议填】CPU 型号(尽量与系统识别名一致, 用于精确匹配)
aliases:                        # 【可选】别名列表(宽松匹配; 例如同款不同写法)
  - "Ryzen 7 8845H"

# ======== 硬件信息(仅供参考/校验, 可不填) ========
logicalCores: 16                # 逻辑核数(线程数)
physicalCores: 8                # 物理核数
tier: high                      # 档位备注: low/mid/high/ultra(纯注释用途)

# ======== 性能参数 ========
# 说明: 这里的值 = "默认模式(n-1基准)" 下的推荐值;
#       用户在前端开启"全速模式"后, 程序会按核心比例自动上调(无需另行填写)
loginWorkers: 22                # 登录并发线程数
workConcurrency: 15             # 答题提交(作业/考试/章测)并发
aiConcurrency: 7                # AI 请求并发
fastVideoWorkers: 11            # 快速视频刷课并发(海旗科技等)
nodeStartInterval: 0.133        # 多任务点节点启动间隔(秒; 越小越快, 下限0.06)
httpMaxConnections: 240         # HTTP 连接池上限
cpuPoolWorkers: 6               # CPU 密集解析进程池 worker 数

# ======== 运行期动态微调(可选覆盖全局默认) ========
tuner:
  enable: true                  # 是否启用负载自适应
  lowLoad: 50                   # CPU 负载低于此值(%) → 提速
  highLoad: 85                  # CPU 负载高于此值(%) → 降速
  minScale: 0.5                 # 系数下限(0.5=最低减半)
  maxScale: 1.5                 # 系数上限(1.5=最多提50%)
```

### 字段取值指引

| 字段 | 类型 | 取值建议（激进档参考公式，N=逻辑核数）|
|---|---|---|
| loginWorkers | 整数 | `round((N-1) × 1.5)`，最低 8。登录是 I/O 密集，可高于核数 |
| workConcurrency | 整数 | `N-1`，最低 2。答题提交并发，过高可能触发平台限流 |
| aiConcurrency | 整数 | `round((N-1) / 2)`，最低 2。受 AI 服务商 QPS 限制 |
| fastVideoWorkers | 整数 | `round((N-1) × 0.75)`，最低 5 |
| nodeStartInterval | 小数 | `2.0 / (N-1)`，下限 **0.06**（防风控，不建议低于此值）|
| httpMaxConnections | 整数 | `max(128, (N-1) × 16)` |
| cpuPoolWorkers | 整数 | `max(2, min(物理核数, (N-1)) - 1)`，一般为物理核数约一半 |

> 懒得算？**什么都不用填**：直接复制本目录的 `_模板_CPU型号.yaml`，只改 `model` 字段也能用（其余留空时程序自动套公式）。

## 三、匹配机制（程序启动时自动执行）

```
① 读取本机 CPU 型号
   Windows: 注册表 ProcessorNameString（如 "AMD Ryzen 7 8845HS w/ Radeon 780M Graphics"）
   Linux  : /proc/cpuinfo "model name"
   其它   : 平台命令兜底
        ↓
② 逐级匹配（任意一级命中即加载；命中的文件会在日志中提示）
   a) 精确:   归一化(型号) == 归一化(文件名或 model 字段)
   b) 别名:   归一化(型号) ∈ 某文件的 aliases 列表
   c) 包含:   文件名型号 ⊂ 系统识别名 (处理 "w/ Radeon 780M Graphics" 等后缀)
        ↓
③ 全部未命中 → 内置公式兜底（按逻辑核数计算，程序正常运行的保证）
   并在日志提示: "建议为本型号添加 cpus/xxx.yaml 以获得最优参数"
```

**优先级提示**：精确 > 别名 > 包含 > 公式。多份文件同时命中时以"精确"的为准。

## 四、新增配置三步走（无需改源码）

1. **看型号**：启动程序，从日志第一屏复制 `[CPU] 检测到: 后面的完整名称`
2. **建文件**：复制 `_模板_CPU型号.yaml` → 重命名为 `{型号}.yaml`（空格换下划线）
   - 例：检测到 `Intel(R) Core(TM) i5-12400F CPU @ 2.50GHz` → 文件名 `Intel_Core_i5-12400F.yaml`，`model` 填 `Intel Core i5-12400F`
3. **填参数**（可只填 `model`，其余留空自动算）→ 保存 → **重启程序即生效**

> 验证是否生效：启动日志出现 `[CPU] 已加载配置: xxx.yaml`。

## 五、常见问题

**Q1：我的 CPU 很老（2008 年后任意型号）能用吗？**
能。未收录型号自动走公式兜底，功能完全正常；添加专属配置只是为了让参数更优。

**Q2：填错参数会怎样？**
程序对每个参数做过区间钳制（如 `nodeStartInterval` 不低于 0.06、并发数有下限），错误值不会导致崩溃。

**Q3：多个 CPU 型号共用一份参数怎么办？**
在 `aliases` 里列出其它型号名即可；或复制多份文件分别指向相同参数。

**Q4：这份配置和 config.yaml 的关系？**
`cpus/*.yaml` 提供**型号级的性能基准**；`config.yaml` 的 `fullCpuMode`/`performanceGear` 是**全局开关**（默认 n-1 / 激进档），两者叠加生效：
`实际值 = 型号配置值 × 全局因子 × 运行期负载系数(0.5~1.5)`。
