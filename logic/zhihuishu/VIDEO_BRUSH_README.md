# 智慧树视频慢刷引擎 (2026-10-12 实战验证)

## 模块
- `video_brush.py` - ZhsVideoBrushEngine: 核心慢刷引擎
- `video_brush_viewer.py` - 9745端口可视化服务器

## 使用
```bash
# 1. 启动可视化(9745)
python logic/zhihuishu/video_brush_viewer.py

# 2. 启动引擎(环境变量配置)
set ZHS_PROFILE=<浏览器profile目录,含登录会话>
set ZHS_URL=https://studyvideoh5.zhihuishu.com/stuStudy?recruitAndCourseId=<lZString编码的课程ID>
set ZHS_PROGRESS=zhs_progress.json
python logic/zhihuishu/video_brush.py

# 3. 浏览器打开 http://127.0.0.1:9745 实时看进度
```

## 关键机制(实战验证)
1. **会话复用免登录**: 复用曾正常登录的浏览器profile目录, 直开课程URL即可完整渲染
   (纯协议会话会被页面拒绝渲染 -> 黑屏; "购买后首次真人进入"后的会话才有效)
2. **课程ID是lZString编码**: stuStudy?recruitAndCourseId=4e5b... (=1000125370), 直开明文ID可能黑屏
3. **点击必须真鼠标**: JS el.click() 无法激活播放器; 必须 CDP dispatch_mouse_event 坐标点击
4. **2倍速=硬检测**: 设 playbackRate=2 后几秒被智慧树检测并踢回首页(https://www.zhihuishu.com/)
   -> 只能1倍速"慢刷"
5. **自动续播(核心)**: 播放器每~3分钟自动暂停(防挂机); 检测video.paused后
   真鼠标点击视频中央(640,360)+video.play() 即可续播, 循环直到播完
6. **进度实时服务端记录**: 页面自然上报, 无接口调用; 2.1节实测 19%->29%->...
7. **被拦判定**: 回登录页 或 (video消失且目录消失) -> 等30秒重进课程页

## 重大更新 (2026-10-12, v190-v199 实战迭代)

### 根因大破案: "视频卡死不加载"的真相
- **根因**: 打开课程页会弹"学习进度提醒"弹窗(el-dialog__wrapper) — 高度>0时**全屏拦截所有点击**,
  导致目录点击/视频点击全部失效 (video dur=null / cur=0 永远不动) — 即"昨晚卡在2.1"的真凶
- **v190诊断实证**: 60秒采样弹窗恒在, 视频从未加载
- **修复原则**: 轻量处理(仅当弹窗有实际高度>30px才点x/ESC); 高度0的wrapper(常见)无需任何处理

### 成功路径 (v193实锤)
点节(真鼠标) -> 3s -> 点视频中央+play -> 视频加载(dur>0) -> 1.0x监控
- 加载窗口30轮x3s, 第5/10/20轮补一次"点中央+play"(保守触发)
- 被拦(回首页/无视频无目录): 等30秒重进

### 三问题处理对策 (已内置引擎)
1. **播放中弹答题**: 检测"AI助教小智给你出题"(topic-item选项) -> 题库/默认答案点选 -> 点"关闭"
2. **自动下一节+已完成跳过**: 目录pct=None=√√ -> 直接跳过; 完成一节后自然切换下一节
3. **完成后不变绿**: 视频到尾(cur>=dur-6)后**重读目录"变绿确认"**(最多等2分钟); 
   变绿才算完成, 否则记"视频完成(待变绿)"下次续刷

### 1.5倍速实测结论 (重要)
- **1.5倍速被前端软限制**: JS设playbackRate=1.5后, rate被打回1.0+视频被周期性暂停
  (表现为"每~10秒续播一次", 有效速度仍是1.0)
- **2.0倍速被硬踢** (回首页)
- **当前引擎以1.0倍速稳定慢刷** (符合"界面下课程最高可选"的实际可用上限)
- **协议层加速路线**: 见 MOGO_ZHS_API_INTEL.md (saveCacheIntervalTimeV2 进度上报接口,
  待逆向完整参数后可实现MOGO式"视频速度(倍)"加速)

### 脚本工程规范 (踩坑教训)
- **★ IDE import重排坑**: "sys.path.insert + os.chdir 后才 import 项目模块"的写法会被
  IDE/格式化器把import重排回文件顶部 -> 导致 ModuleNotFoundError 时好时坏
  **正解: importlib动态导入** (import importlib; nodriver=importlib.import_module("nodriver"))
- **日志实时性**: 脚本内 sys.stdout 重定向到文件时必须 print=partial(print,flush=True),
  否则缓冲导致运行中看不到日志
- **profile锁**: 浏览器异常退出会残留 Singleton* 锁, 重启前需清理 + 杀对应chrome进程

## ★★★ v213-v221 重大修复: "视频卡loading" (2026-10-13)

### 现象
点击目录节后 video 永久卡死: `dur=0` + `networkState=2(LOADING)` + `readyState=0`,
60秒+不恢复、不报错。点击/滚动/命中校验全部正常、initVideo 接口也正常发出。

### 排查链 (逐层排除)
1. Python requests 直接下载视频文件: **206/1024字节/0.06s 完全正常** → 网络层无问题
2. 浏览器内 fetch 同一视频文件: **206/1025字节 成功** → 浏览器网络栈也无问题
3. 但 video 元素就是 forever loading → **锁定 Chrome 媒体管道层**
4. 铁证: 同文件 Python/浏览器fetch 都能下载，唯独媒体管道拿不到数据

### 根因 (双因素)
1. **媒体缓存损坏**: profile 的 Cache/Code Cache 目录条目损坏后,
   媒体请求被缓存层短路(资源记录出现 dur=3ms/size=0 的"空请求")
2. **QUIC黑洞**: 视频CDN(wsvideo=火山引擎)支持HTTP/3(QUIC/UDP),
   本网络环境对UDP大流量处置不良 → Chrome 卡在QUIC超时倒计时,媒体管道不fallback

### 修复 (v221已固化)
1. **启动前清缓存目录**: Cache / Media Cache / Code Cache / GPUCache
2. **浏览器启动参数**: `browser_args=["--disable-quic"]`
3. 验证: 清缓存+禁QUIC后, 7.1/8.1视频均15秒内 readyState=4 正常加载播放
4. 以后再遇"视频卡loading": 先清缓存重试, 其次查QUIC/网络环境
